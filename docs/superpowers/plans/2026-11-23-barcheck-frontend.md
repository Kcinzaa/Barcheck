# Barcheck Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mobile-first React app where bar staff fill Bar Report and Store Requisition at the bar, stored per (bar × date × item) so a monthly summary and Excel export need no manual tallying.

**Architecture:** Pure-TS domain layer (oz math, report calculation, monthly aggregation) with no React imports, a thin localStorage repository behind an interface (swappable for a backend later), and React pages built on those. Quantities are held internally as integer-free decimal **oz** and shown as bottles + oz.

**Tech Stack:** Vite, React 18, TypeScript, react-router-dom, Vitest + Testing Library, SheetJS (`xlsx`) for export, plain CSS with CSS variables.

**Spec:** `docs/superpowers/specs/2026-11-23-barcheck-frontend-design.md`

## Global Constraints

- Mobile-first; touch targets ≥ 44px; numeric inputs use `inputMode="decimal"`.
- Thai and English item names must render correctly (UTF-8, Thai-capable font stack).
- No backend, no login in v1; persistence is `localStorage` only, key prefix `barcheck:`.
- Record key is unique per (barId, date `YYYY-MM-DD`, form `bar|requisition`); reopening edits the existing record.
- Closed is **computed** by the system. Optional "counted" value may be entered; show variance (counted − computed) and warn when ≠ 0.
- Calculation (all in oz): `total1 = open + dailyStore + transferIn`; `total2 = total1 − transferOut`; `closed = total2 − sale`. `sale` is in oz.
- Bar Central ingredient form, item-list admin, backend, auth are **out of scope**.
- Drafts autosave; leaving the page never loses typed data.

## Review Focus

- Sale larger than available stock → Closed would be negative: show it in red with a warning, still allow save.
- Blank fields must count as 0, not NaN; a fully untouched row must not be counted as "filled".
- oz input ≥ bottle size (e.g. 30 oz on a 23 oz bottle) must normalize to 1 bottle 7 oz, never display "30 oz".
- Decimal input with comma (Thai/EU keypads, `7,5`) must parse as 7.5.
- Monthly summary for a month with missing days or a bar with no records shows an empty state, not a crash or zeros that look like real data.

```
  App.tsx  main.tsx  styles.css
scripts/build-seed.py      # builds items.json from the Excel files + PDF transcription
```
