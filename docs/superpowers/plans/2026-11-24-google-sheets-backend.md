# Google Sheets Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sync Barcheck's reports and requisitions to a Google Sheet through an Apps Script web app, offline-tolerant, with item sizes editable in the sheet.

**Architecture:** `repo` (localStorage, synchronous) stays the local source of truth. A write-behind sync layer queues each successful save, pushes to an Apps Script Web App (`POST`, JSON as `text/plain` to avoid a CORS preflight) and pulls a bar+month on page entry. The Apps Script code is pure functions over a small `store` adapter so it can be unit-tested in Vitest without Google.

**Tech Stack:** TypeScript/React/Vitest (existing), Google Apps Script (V8, plain JS in `apps-script/Code.gs`), `fetch` mocked in tests.

**Spec:** `docs/superpowers/specs/2026-11-24-google-sheets-backend-design.md`

## Global Constraints

- Sheet tabs exactly: `Reports`, `Requisitions`, `Items`, `Summary`, `Keys`.
- Auth: one random access key per bar, checked by the script on every request; wrong/missing key → `{ok:false, error:'unauthorized'}`; keys are generated by `setup()` and listed in tab `Keys`.
- Request: `POST` body `JSON.stringify(...)` sent with `Content-Type: text/plain;charset=utf-8`. Actions: `push`, `load`, `items`. Responses are JSON `{ok:boolean, ...}`.
- Conflict rule (record level, no clock comparison): a record with a pending (unsynced) local change is never overwritten by a pull; otherwise the pulled remote record replaces the local one. `push` for a (barId,date,form) replaces all of that record's rows atomically under `LockService`.
- Local-first: no UI path waits on the network; saving never fails because the network does.
- `sizeOz` snapshot: every persisted report row carries `sizeOz` (the item's size when saved); calculations use `row.sizeOz ?? item.sizeOz`.
- Existing 161 tests keep passing; do not change existing test expectations except where a signature change forces it (state which).
- No secrets in the repo; the script URL and keys are entered by the user in the app's Settings page and stored in localStorage (`barcheck:sync:config`).
- Commits end with: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_013yWv4gzswF8EUkyCFToA8g`.

## Review Focus

- Offline then online: queued saves flush in order, each sends the LATEST local state, no duplicates, queue survives reload (test in Task 3).
- Two phones edit the same bar/day: the later push wins at record level; the loser's phone must receive the winner on next pull unless it has pending changes — documented, tested (Task 3/5).
- Wrong or rotated key: sync state `error:unauthorized`, local data untouched, saving still works (Task 3).
- Script URL down / Apps Script returns an HTML error page / non-JSON / timeout: treated as a failed attempt with backoff, never a crash or a false "synced" (Task 3).
- Malformed or foreign records in a pull response (bad shape, other bar) are skipped, never written (Task 1/3).

### Task 3: Sync client, config and engine

**Files:**
- Create: `src/sync/config.ts`, `src/sync/client.ts`, `src/sync/engine.ts`, `src/sync/queue.ts`; Test: `src/sync/*.test.ts`

**Interfaces:**
- Consumes: Task 1 `repo.onSaved`, `repo.mergeRemote`, `repo.getReport/getReq`, `repo.listReports`.
- Produces:
  - `config.ts`: `type SyncConfig = { url: string; keys: Record<string, string> }`; `getConfig(): SyncConfig | null`; `setConfig(c: SyncConfig | null): void`.
  - `queue.ts`: `type QueueItem = { form: 'report'|'req'; barId: string; date: string }`; `enqueue(i)` (dedupes by key, keeps first position), `peek()`, `remove(i)`, `size()`, `pendingKeys(): Set<string>` (entries formatted `"{form}:{barId}:{date}"`, the same format `repo.mergeRemote` expects); persisted in `barcheck:sync:queue`.
  - `client.ts`: `createClient(fetchImpl = fetch, cfg): { push(item: QueueItem, payload): Promise<void>; load(barId, month): Promise<{reports: ReportRecord[]; reqs: ReqRecord[]}>; items(barId): Promise<ItemRow[]> }`; throws `SyncError('unauthorized' | 'network' | 'bad_response' | 'timeout')`; 15 s timeout; non-JSON or `ok:false` handled as above.
  - `engine.ts`: `type SyncState = { status: 'unconfigured'|'idle'|'syncing'|'offline'|'error'; pending: number; error?: string; lastSyncedAt?: string }`; `startSync(): () => void` (subscribes to `repo.onSaved`, flushes now and on `online`/`visibilitychange`, retries with backoff 5 s→60 s, max one flush in flight); `getState()`, `subscribe(cb): () => void`; `pull(barId: string, month: string): Promise<void>` (merges via `repo.mergeRemote` with `pendingKeys()`); `retryNow()`.
